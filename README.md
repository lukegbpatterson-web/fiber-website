# bayzl — landing pages (basilseedfiber.com)

Three static landing-page variants for the bayzl lemon-lime fiber blend: the landing pages for a Meta ads A/B test of three packaging designs, same copy and layout, scored on waitlist join rate. Served by
GitHub Pages at **basilseedfiber.com** (the `CNAME` file), straight from `main`.
The pages are generated by a small local script (`node build.mjs`); the server needs no build.

The site that was live before this (basil-seed version) is preserved at the
tag [`v1-bayzl-landing`](https://github.com/lukegbpatterson-web/fiber-website/tree/v1-bayzl-landing).

## How the pages are made
The three pages are **generated** from one template so they can't drift apart:

- `src/page.html` (all copy and structure), `src/join.html` (the email form + success state, used twice), `src/privacy.html`
- `variants.config.json`: the only place that says what differs per page (hero image, `theme-*.css` palette + logo, robots)
- `node build.mjs` writes `index.html`, `2/index.html`, `3/index.html`, `privacy/index.html` (commit the output)

| Page | Variant | Box | Look | Background |
|---|---|---|---|---|
| `/` | A | illustrated sage | default (`styles.css`) | `bg-dust.js` |
| `/2/` | B | soft photo gradient | `theme-zest.css` | `bg-slices.js` |
| `/3/` | C | bold yellow-to-dark-green | `theme-treat.css` (Fraunces type) | `bg-bubbles.js` |

**TEST ONLY:** all three are `noindex, nofollow` while the Meta ads test runs. To revert `/`, see `_robotsNote` in `variants.config.json`.

### Swapping hero images
Drop `assets/product-hero-a.webp`, `product-hero-b.webp`, `product-hero-c.webp` in place (until they exist the old files are used), then:
```bash
python scripts/optimize-images.py    # resizes to 800px wide WebP under 200 KB (pip install pillow)
node build.mjs
```

## Files
- `assets/styles.css` shared styles; `theme-zest.css` / `theme-treat.css` per-variant looks; `bg-*.js` per-variant hero backgrounds
- `assets/config.js` Pixel ID, GA4 ID, Apps Script URL (nothing secret)
- `assets/tracking.js` Meta Pixel + GA4 (scripts load after the page `load` event so they don't slow the hero image)
- `assets/main.js` form, success state + survey, attribution capture, sticky mobile bar
- `apps-script/Code.gs` waitlist backend + Conversions API (deploy steps in `apps-script/README.md`)

## Preview locally
```bash
node apps-script/test-local.js --serve   # http://localhost:8137 (and /2/, /3/) with a fake backend
```

## Waitlist data
Every submit appends a row to the Google Sheet: timestamp, email, source URL, variant (A/B/C), `utm_source`, `utm_campaign`, `utm_content`, `fbclid`, `event_id`, `capi_status`, and the two optional survey answers. UTMs are read from the URL and kept for the session.

## Tracking
- **Meta:** Pixel `PageView` on load. On a confirmed new join: browser `Lead` + server (Conversions API) `Lead`, deduplicated by a shared `event_id`, with `content_name` = variant. No health terms are sent.
- **GA4:** `G-0LE6VK6ZT3`, plus a `generate_lead` event (with `variant`) on a confirmed new join.

## Deploy
Push to `main`; GitHub Pages republishes (about a minute). Deploy the Apps Script first (see its README).

## Notes
- Respects `prefers-reduced-motion` (reveals, floating box and the hero background effects turn off).
- Responsive down to mobile; keyboard-focusable with visible focus rings.
- Hero reveals are pure CSS; section reveals use IntersectionObserver (`assets/main.js`). Three.js (for the per-page hero background) is only fetched after the page has loaded and settled, and is skipped for reduced-motion / data-saver users.
- The hidden footer page-switcher between variants was removed so ad traffic can't cross over between A/B/C.
